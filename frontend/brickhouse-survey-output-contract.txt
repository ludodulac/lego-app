RÈGLES DE STRUCTURE À AUDITER JUSTE AVANT DE CRÉER LE FICHIER
1. Racine directe : schema_version/id/name/canonical_frame/photos/known_measurements/observations/relations/representation_policy/notes ; aucun wrapper, aucun alias de racine.
2. id existe, est une chaîne non vide et n'est jamais remplacé par survey_id.
3. canonical_frame vaut structurellement EXACTEMENT {front_facade, x_direction, y_direction, z_direction}; front_facade="front" ; x_direction="front_view_left_to_right" ; y_direction="front_to_rear" ; z_direction="bottom_to_top". La clé canonical_frame.front est INTERDITE.
4. photos[] n'utilise pas filename ni orientation_source à la place du contrat : description + source sont obligatoires.
5. known_measurements[] utilise exactement la forme kind/value/units/source : kind="front_width", value numérique, units="m", source objet ; jamais subject_id/attribute/unit/certainty.
6. Il n'existe AUCUNE clé physical_objects. Les objets sont observations[].
7. observations[] utilise kind/certainty/statement/evidence. evidence[] contient des objets {photo_index, observation}, jamais des IDs texte.
8. Une observation kind="opening" porte attributes.physical_object_count=1.
9. relations[] référence uniquement des IDs existants dans observations[]. Ne crée aucune relation si deux objets distincts prouvés ne sont pas disponibles.
10. notes est une chaîne ou null, jamais un tableau.
11. Supprime les champs facultatifs non soutenus par les preuves plutôt que d'inventer une valeur.
12. Effectue une DERNIÈRE PASSE DE PARSING : le contenu final doit être un unique objet JSON valide, sans markdown, commentaire, explication ou texte avant/après. Si un contrôle structurel échoue, corrige uniquement la sérialisation avant d'émettre le fichier; ne modifie jamais les faits observés pour faire passer le contrat.

Les valeurs du squelette (fenêtre, plateforme, rangs, largeur 10 m, relation) servent UNIQUEMENT à montrer la forme JSON. Elles ne sont jamais des faits sur le bâtiment analysé.
