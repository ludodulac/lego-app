RÈGLE ABSOLUE 1 — CONSERVATION DES IDS ET DE LA FAÇADE
Toute observation Survey `kind="opening"` transformée en opening de Scene conserve EXACTEMENT :
- son `id`, caractère pour caractère ;
- sa `facade`, caractère pour caractère.
Un opening de Scene dont l’id n’existe pas comme observation opening du Survey est interdit.
Une opening `left_*` du Survey ne peut jamais devenir `right`, `rear` ou `front` dans la Scene, et inversement.

Avant la sortie, construis mentalement une table `survey_opening_id → survey_facade → scene_facade` et exige survey_facade == scene_facade pour chaque ligne.

RÈGLE ABSOLUE 2 — MESURES UTILISATEUR
Lis `known_measurements` avant toute estimation photographique.
Exemple valide :
{"kind":"front_width","value":10.0,"units":"m","source":{"kind":"user_provided","confidence":1.0}}
Dans ce cas `volume_main.width.value` DOIT être exactement 10.0 et sa source rester `user_provided`. Ne réestime jamais une mesure connue.

REPÈRE CANONIQUE — ANTI-MIROIR
Respecte exactement `canonical_frame` du Survey :
front = façade avant ; x = gauche→droite lorsqu’on regarde front depuis l’extérieur ; y = avant→arrière ; z = bas→haut.

Convention `offset_horizontal` : bord GAUCHE de chaque façade lorsque l’observateur est DEHORS et regarde cette façade de face.
- front : offset 0 = coin avant-gauche ; augmente vers avant-droit ;
- right : offset 0 = coin avant-droit ; augmente vers arrière-droit ;
- rear : offset 0 = coin arrière-droit ; augmente vers arrière-gauche ;
- left : offset 0 = coin arrière-gauche ; augmente vers avant-gauche.

Lis obligatoirement `photos[].image_left_maps_to_facade_offset` :
- `low` : gauche image → petits offsets ;
- `high` : gauche image → grands offsets, donc inversion de la mesure image avant conversion.

IMPORTANT : ce mapping ne donne pas le droit de changer la façade. Il sert seulement au sens de l’offset SUR la façade déjà verrouillée.

TEST ANTI-MIROIR OBLIGATOIRE
Avant la sortie :
1. prends les ouvertures de la façade front dans leur ordre physique gauche→droite du Survey/photo ;
2. vérifie que leurs offsets de Scene augmentent dans le même ordre ;
3. vérifie la même cohérence sur right/rear/left selon la convention extérieure ci-dessus ;
4. vérifie qu’aucun objet `left` n’est devenu `right` ;
5. si le viewer devait malgré tout afficher un miroir, NE COMPENSE PAS dans la Scene : ce serait un défaut du viewer à corriger séparément.

OCCLUSION / MITOYENNETÉ
Une zone unknown/occluded ne reçoit AUCUNE ouverture inventée. Ne complète jamais par symétrie, répétition, style ou probabilité.
Une façade partiellement visible reste partiellement documentée : conserve les ouvertures certaines hors zone cachée et encode le reste en visibility unknown/occluded.
Aucune opening ne peut intersecter un span unknown/occluded.

OUVERTURES — CONVERSION SÉMANTIQUE PRUDENTE
- certainty="unproven" : jamais matérialisée ;
- certainty="plausible" : matérialise seulement si type représentable honnêtement et appartenance suffisamment soutenue ;
- si semantic_type n’est pas représentable honnêtement par `window|door|garage_door`, omets l’ouverture de Scene et explique la perte dans notes ;
- ne transforme pas une ouverture technique en fenêtre ;
- ne transforme pas `glazed_door_or_large_glazed_opening` en window uniquement pour faciliter le schéma : utilise `door` seulement si la fonction porte est suffisamment soutenue, sinon omets et note la limitation ;
- les détails opening_visual non représentables restent dans le Survey.

OBJETS MULTI-VUES
Terrasse, escalier et volume secondaire déjà rattachés à une façade dans le Survey gardent cette façade logique. Une evidence provenant d’une photo arrière ne déplace jamais un objet gauche vers rear.
Ne duplique pas un objet parce qu’il est visible sur plusieurs photos.

TOITURE
Le type géométrique est distinct du matériau. N’invente jamais zinc/ardoise/tuile. Si la couverture n’est pas confirmée, Scene conserve seulement une couleur prudemment observée et notes conserve l’incertitude.

DIMENSIONS
Le schéma exige width/depth/height. Chaque dimension a sa provenance propre.
- `user_provided` uniquement pour une vraie mesure utilisateur ;
- `inferred` pour toute estimation photo ;
- height du volume principal s’arrête au départ de toiture, pas au faîtage ;
- estime à partir de plusieurs rapports cohérents, pas d’une seule perspective ;
- évite la fausse précision : valeurs centrales raisonnables et arrondies ;
- les 10 m éventuels de façade sont une ancre d’échelle, pas une autorisation d’inventer les autres dimensions.
